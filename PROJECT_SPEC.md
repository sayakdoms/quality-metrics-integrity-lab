# Project Specification — Quality Metrics Integrity Lab

## Purpose
Turn the BML-536 Quality Management presentation **When Quality Metrics Lie** into an interactive analytical application that demonstrates how KPI pressure can separate reported quality from underlying process quality.

## Core thesis
A quality metric can improve while the process it represents deteriorates. The application explores the conditions that make this divergence more likely and the managerial controls that can reduce measurement-integrity risk.

## MVP modules
1. **Quality Mirage Simulator** — actual vs reported defect-rate trajectories.
2. **Metric Integrity Score** — vulnerability based on single-metric dependence, stakes, manipulability, and weak customer linkage.
3. **Gaming Mechanisms** — classification, timing, and sampling.
4. **SPC Integrity** — real vs sanitised p-chart data.
5. **Cost of Quality** — internal failure shifted into external failure exposure.
6. **Metric Audit** — five-question measurement-integrity checklist.
7. **Measure + Context + Behaviour** — managerial interpretation framework.

## Non-goals for v0.1
- No claim of causal or empirical validation.
- No real-company accusations or inferred misconduct.
- No production-grade audit or compliance conclusions.
- No machine learning until the basic simulation logic is transparent and testable.

## v0.2 candidates
- CSV upload for user-owned quality data.
- Configurable p, np, c and u charts.
- Process capability module (Cp/Cpk) with data-integrity warnings.
- Scenario comparison and downloadable PDF/CSV report.
- Sensitivity analysis for gaming pressure and incentive design.
- Better provenance and methodology page.

## Portfolio positioning
This project is best described as an **educational quality-analytics simulator and decision-support prototype**.
